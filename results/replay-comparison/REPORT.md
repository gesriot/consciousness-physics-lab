# Сравнение повторов по решениям

Режим `exact` сохранён: все нетайминговые значения сравниваются точно.
Режим `decisions` точно сравнивает рабочие вердикты, флаги, метки точности,
целые счётчики, строки, структуру, идентичность протокола и канонические входы.
Измеренные вещественные выходы больше не имеют порога PASS/FAIL. Для каждого
пути поля (индексы массивов объединены) выводятся количество значений и изменений,
максимальные абсолютное и симметричное относительное расхождения; нечисловые
бесконечные/NaN значения учитываются отдельным счётчиком. Поля входного запроса
остаются точными даже при изменении на один младший бит. Параметры `--atol` и
`--rtol` оставлены для совместимости интерфейса, но не ограничивают выходные числа.

Полные теневые траектории, карты покрытия и их сводки E007/E009/E011 вынесены в
отдельный список. Расхождения порядка при вычитании близких округлённых величин
могут менять теневые вердикты, сходимость и диагностический fallback_steps;
рабочие флаги и счётчики при этом не исключены из проверки. В E011 также
отделены явно названные счётчики shadow_cells, shadow_work и shadow_by_model.
Замороженный проверяющий E011 не использует оценку порядка; новые расхождения
его теневых меток требуют самостоятельного научного рассмотрения. Перечень известных
причин не доказывает безвредность любого нового диагностического расхождения.

Новые E011 intake_sha256 считаются по каноническому intake_channel, а не по
файлу с окружением. reference_audit_sha256 считается по каноническому содержимому
проверки эталона: это контроль происхождения численной проверки, не идентичность
входа. Такой хеш закономерно может отличаться при численных изменениях самого
аудита. Оба архивных хеша отдельно отображаются как происхождение; вместо
непереносимого старого intake_sha256 сравниваются сами канонические входы.
Метки и счётчики вложенного аудита эталона остаются обязательными. Файловый
source_sha256 в метаданных replay сохраняет полезную точную идентичность архива.

## Проверки

В предоставленном репозитории доступны только Linux x86_64 архивы. Файлов
описанных владельцем macOS arm64 повторов в архиве нет; их фактическое
сопоставление здесь не заявляется.

- E009: сохранённый исходный прогон и bundled replay дают PASS по решениям.
- E011: сохранённый исходный прогон и repeat дают PASS по решениям.
- Контролируемое изменение всех выходных float посредством nextafter, без
  изменения входов: 158029 полей E009 и 126469 полей E011. Оба сравнения дают
  PASS по решениям и FAIL в exact с тем же числом численных различий.
- Отдельно перечислены 68386 синтетических диагностических изменений E009 и
  36522 изменения E011.
- Изменение одного рабочего accepted обнаружено в обоих отрицательных контролях.
- 15 модульных тестов прошли, включая точность входов, протокола, счётчиков,
  разделение диагностики и сводку численных расхождений. Контроль E011 изменяет
  восемь теневых меток и счётчиков: PASS по решениям, восемь отдельных
  диагностических различий. Изменение рабочей сходимости, cells_solved или
  decision_cells в трёх отдельных контролях приводит к FAIL.

Команды воспроизведения:

```
python3 scripts/audit_replay_comparison.py
python3 -m unittest tests.test_experiment_replay -v
python3 scripts/compare_experiment_runs.py results/surface-order/results.json results/platform-replay/e009-replay.json --mode decisions
python3 scripts/compare_experiment_runs.py results/E011-extrapolation/results.json results/E011-extrapolation/repeat.json --mode decisions
```

Машиночитаемый аудит и полные сводки полей сохранены рядом с этим отчётом.
PASS decisions не означает точного воспроизведения или полной научной
эквивалентности численных траекторий.
