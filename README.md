# Сознание и агент-физик: исследовательская лаборатория

Рабочий репозиторий долгосрочного исследования. Здесь соединяются строгая
постановка задач, понятное объяснение и проверяемый лабораторный журнал.
Это не готовая диссертация и не утверждение о создании сознания.

## Начать

Python 3.10+; проверено на Python 3.12.14 / NumPy 2.3.5.

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements-tested.txt
./scripts/check.sh
python3 -m lab.runner vendor/sphere-thermal-cli/examples/single_compare.json > results/local-run.json
```

Последняя команда делает три измерения времени CLI вместе с запуском Python.
Это минимальная основа инфраструктуры будущего агента: пока только
детерминированный вызов физического инструмента и протоколирование результата.
Этот исходный runner не содержит LLM; следующий вычислительный контроллер описан ниже.

## Правила

MANUSCRIPT.md – связный научный текст: вопросы, идеи, словесная постановка опытов, ключевые числа, отрицательные результаты и пределы выводов. Хеши, число тестов, окружения, seeds, имена файлов, команды и история проверок остаются в README, протоколах и отчётах. Идентификаторы реализации заменяются определёнными русскими терминами; на каждый опыт в рукописи допускается не более одной ссылки «подробности» на отчёт. Перенесённые технические сведения версии 0.2 сохранены в [редакционном отчёте](results/manuscript-editorial/version-0.3.md).

Отделять факт наблюдения, вычислительный вывод, интерпретацию и гипотезу.
У каждой численной записи должны быть вход, версия кода, окружение, единицы и
критерий успеха. Отрицательные результаты сохранять. Сначала регистрировать
протокол, затем запускать. Исправления оформлять отдельными коммитами.
Нельзя считать согласие двух формул независимой физической валидацией.
Нельзя считать правдоподобный самоотчёт доказательством сознания.

## Воспроизведение E007 и E008

По умолчанию требуется ровно Python 3.12.14 / NumPy 2.3.5 / SciPy 1.17.0
и чистые отслеживаемые файлы. Сначала коммит протокола, затем коммит
реализации, затем генерация данных. Новые JSON сохраняют версии, ОС,
архитектуру, конфигурацию BLAS/LAPACK NumPy и SciPy, git_head,
protocol_commit, protocol_sha256 и хеши исходников. Старые архивы неизменны;
отсутствующие сведения об их платформе не восстанавливаются догадкой.

Точное совпадение нетайминговых полей относится к повторам на исходной
платформе и исходной реализации, а не ко всем ОС и библиотекам. Владелец
проверил macOS arm64 / Python 3.12.13 / NumPy 2.3.5 / SciPy 1.17.0:
вердикты, решения, метки и счётчики совпали, числа различались примерно
на 10⁻¹⁴. В E008 повторная генерация входов дала другие хеши из-за последнего
бита libm. Это сообщение владельца, не новый сохранённый результат этого
репозитория и не доказательство переносимости на любую платформу.

Для межплатформенной проверки используйте сохранённые запросы, а не только
seed. `--replay` читает сохранённые tasks для E007/E009 или intake_channel для E008/E010/E011 из results.json,
сохраняет двоичные значения входных float, проверяет сохранённые входные хеши и
записывает SHA-256 всего исходного архива. Порядок условий остаётся задан
зарегистрированным order_seed. В E007 масштаб |zT| для анализа покрытия
восстанавливается из сохранённого запроса; это может изменить последний бит
производной величины относительно первоначального сэмплирования.

```sh
./scripts/check.sh
python3 -m lab.verifier_stress --replay results/verifier-stress/results.json --output results/local/e007-replay.json
python3 scripts/compare_experiment_runs.py results/verifier-stress/results.json results/local/e007-replay.json --mode decisions --rtol 1e-12
python3 -m lab.common_mode --replay results/common-mode/results.json --output results/local/e008-replay.json
python3 scripts/compare_experiment_runs.py results/common-mode/results.json results/local/e008-replay.json --mode decisions --rtol 1e-12
```

На другой версии Python добавьте к запуску явно обоснованный
`--runtime-override 'Cross-platform replay audit: Python 3.12.13'`.
Причина и фактические версии сохраняются в новом JSON; проверка чистоты
отслеживаемых файлов остаётся обязательной. Существующий выходной файл
не перезаписывается: выберите новый путь. Архивы результатов не обновляются.

Режим сравнения по умолчанию `--mode exact` оставляет точное сравнение
всех нетайминговых полей, включая происхождение. `--ignore-git-head`
исключает только HEAD позднего коммита. После изменения реализации старые
хеши исходников закономерно отличаются, и exact не должен проходить.
В режиме `--mode decisions` измеренные вещественные выходы не дают FAIL:
для каждого поля выводятся максимальные абсолютные и относительные расхождения.
Рабочие решения, вердикты, метки, целые счётчики, структура, канонические входы
и идентичность протокола сравниваются точно. Полные теневые пути E007/E009/E011,
диагностические флаги и сводки покрытия выведены отдельно; рабочие флаги остаются
обязательными. Параметры atol/rtol сохранены для совместимости интерфейса.
Среда, HEAD, хеши исходников, аудит эталона и replay относятся к происхождению.
Новые входные хеши E011 основаны на каноническом intake_channel, а не файле с
окружением; хеш аудита основан на его каноническом содержимом. PASS decisions
не означает полной научной эквивалентности. Обе архивные пары E009/E011 прошли,
как и контролируемые изменения 284 498 выходных float; изменение рабочего
решения обнаружено. Реальных macOS-архивов в поставке нет.
[Отчёт и отрицательные контроли](results/replay-comparison/REPORT.md).
В обоих режимах исключаются
из сравнения поля с окончанием seconds. Дополнительная послерезультатная проверка
E007: `python3 scripts/audit_e007_high_precision.py` из корня репозитория,
использует mpmath 1.3.0 и 60 десятичных знаков.
Она не меняет основной закреплённый стек или зарегистрированные меры.

Материалы внимания остаются отдельным архивом и в эти опыты не включались.

## Перенос замороженной проверки за пределы разработки

E011: 192 новые независимые задачи, четыре когорты по 48, восемь зависимых
условий на задачу. Сгущение 4, замороженная оценка неопределённости,
трёхвердиктное решение, контроль разрешения, привязка запроса и четыре
инварианта зафиксированы до данных; полоса порядка не используется.
Версия рукописи 0.4 отражает новые научные результаты после редакционной 0.3.

- A, |zT|=10⁶..10⁸: 18/192 промахов покрытия на пути исходного шара,
  максимум ошибка/оценка 1.87682. На всех трёх модельных путях 207/576;
  максимум 76.4926 относится к общей ошибке масштаба, а не исходному шару.
- B, почти мнимая частота: у исходного шара 0/192 промахов.
- C, допуск 10⁻⁶..10⁻⁴: все 48 чистых значений неточны при пределе 4096 мод,
  все получили численный вердикт о нарушении, ни одно не принято.
- K, контроль: приняты все 45 чистых точных значений из 48 задач.

Во всех когортах ложных принятий 0/384 зависимых записей; промахов покрытия
на решающих шагах 0/104, 0/143, 0/140, 0/138 (единица: задача/модель/сетка).
Чистые точные принятия: A 47/47, B 45/45, C точных нет, K 45/45.
Чистых ложных отказов инвариантов нет. Вердикты о нарушении на точных
значениях: 90/34/1/39; все относятся к неверным общим моделям, обнаруженным
инвариантами, а не к численным нарушениям допуска. Эти отказы не скрыты.

До решений все 96 запросов A/B проверены 60-значной формулой: максимальная
ошибка analytic 1.75482·10⁻¹⁶, переход на резервный эталон не понадобился.
Точный повтор всех научных нетайминговых полей, включая диагностику, прошёл
в закреплённой среде; метаданные происхождения перечислены отдельно.
Это условная воспроизводимость, не межплатформенная гарантия.
На самой тонкой сетке исходный шар A имеет δ/h_s≥1.549: режим неразрешённого
слоя даже при 4096 ячейках в этой выборке не достигнут. Частота пробы
асимптотики осталась zT=10⁴; её допуск не проверен непосредственно на 10⁸.

## Совпадающие признаки и третья реализация E013

Рукопись версии 0.6 включает смесь двух пластин, совпадающую с шаром по
нормировке, среднему, второму моменту и ведущему высокочастотному коэффициенту.
Все четыре пробы пропустили смесь. В 96 парных задачах D и D с признаками дали
23 ложных принятия (6 в широкой и 17 в промежуточной когорте); добавление
независимой коллокации исходного радиального уравнения снизило их число до 0.
Третья реализация отдельно не дала ложных принятий; единственный неразрешённый
исход относится к одной пластине. D здесь соответствует E010, а не E011 V.

Для чистого шара D и комбинированные политики приняли 87 из 88 точных ответов,
третья реализация отдельно 88 из 88. Для смеси комбинированная политика отвергла
3 точных ответа, отвергавшихся уже D; для пластины признаки отвергли 42 случайно
точных ответа. Положительная смесь трёх пластин дополнительно совпала по третьему
моменту. Проверены отсутствие точных повторов запросов внутри E013 и пересечений
с сохранёнными E009/E010/E011. Это не делает парные политики независимыми.

[Протокол](experiments/E013-matched-mixture.md),
[полный отчёт](results/E013-matched-mixture/summary.md),
[вывод параметров](results/E013-matched-mixture/derivation.md).
Сохранены полный основной прогон, точный повтор, исходные запросы, проверки
пересечения и цены всех политик. Прямое exact-сравнение сохранило FAIL по

### Исправление проверки после шумового прогона

Первый и обычный подтверждающие прогоны прошли исходный независимый аудит.
Шумовой исполнитель завершил все 12 серий, но исходный аудитор не применял
зарегистрированный сдвиг последнего бита к оценкам до округления. В 45 BU-снимках
граница округления дала различие 1e-9 в оценке невыбранного канала. Из-за двух
сохранённых полей это 90 численных различий в 42 из 2 930 файлов. Полная отдельная
сверка не нашла изменений реальных действий, защищённых вердиктов, цен, графа,
очередей, меток или итогов.

Исходные FAIL, строгое сравнение и манифест шумового архива сохранены отдельным
коммитом до исправления. Последующее исправление проверяющего кода учитывает
зарегистрированный шум при независимом восстановлении оценок и отделяет их
численный дрейф от точно сравниваемых решений. Это проверка исходных сохранённых
байтов, не новый физический прогон и не изменение расписания по результатам.
[Новая ограниченная запись происхождения](binding/results/B003/noise-verifier-correction.json) отделена от прежней переносимости;
исторические доказательства совместимости не переписаны. Подробная хронология,
регрессионные тесты и результаты повторной проверки находятся в отчёте B003.
